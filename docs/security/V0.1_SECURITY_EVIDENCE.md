## Data flow

```text
                      ForgeAI instance (one customer boundary)
 ┌──────────────────────────────────────────────────────────────────────────────┐
 │ upload / forgeai ingest / source sync                                        │
 │        │ extract text in memory (originals are not stored)                   │
 │        ▼                                                                     │
 │ normalize → chunk ──► SQLite: documents, chunks (plaintext), chunks_fts      │
 │        │                                                                     │
 │        └─► [sensitive-data guard] → [audit provider.invoke] → [egress check] ─┼──► embedding provider
 │                                                                              │
 │ question ─► query embedding (same guard/audit/egress path) ──────────────────┼──► embedding provider
 │        ├─► vector scan + FTS5 + RRF (local)                                  │
 │        ├─► optional LLM rerank (guard/audit/egress) ─────────────────────────┼──► LLM provider
 │        └─► RAG prompt = system prompt + numbered context + question          │
 │                 └─► guard → audit → egress ──────────────────────────────────┼──► LLM provider
 │                                                                              │
 │ traces/spans: names, models, tokens, cost, errors (no prompts or chunks)     │
 │ audit_events: actions, actors, IDs, fingerprints (no secrets or content)     │
 │ evaluation_results: generated answers, judge reasons (customer-derived)      │
 │ secrets: AES-GCM under FORGEAI_MASTER_KEY                                    │
 │                                                                              │
 │ deletion: forgeai data delete-* / DELETE API → cascade + FTS purge;          │
 │           forgeai data compact → FTS merge, WAL truncate, VACUUM             │
 └──────────────────────────────────────────────────────────────────────────────┘
```

Only the three arrows leaving the box carry customer text. Every one of them passes the same three layers, in order: the sensitive-data guard, the audit decorator, and the egress transport.

## Threat model

| Threat | Mitigation in v0.1 | Residual risk and owner |
|---|---|---|
| Credential theft (provider keys) | Keys are read from env or stored AES-GCM encrypted with the secret name as AAD; `secret set` reads stdin only; keys are never logged or audited | Theft of `FORGEAI_MASTER_KEY` or the process environment exposes keys. Operator protects the host and rotates keys |
| Database theft | Secrets are encrypted. `doctor` reports whether an encrypted volume is declared, and the production profile fails without it | Chunk text, FTS data, and evaluation answers are plaintext in SQLite. Operator must use an encrypted volume |
| Cross-customer access | Production profile is single-tenant: one instance per customer; `doctor` fails when shared demo accounts are enabled in production | Running several customers in one instance is unsupported. Operator deploys separate instances |
| Accidental external egress | `local_only` blocks unapproved destinations before transmission; `deny_sensitive`/`redact_known_patterns` stop known identifier formats; every provider call is audited with its endpoint origin | `external_allowed` + `allow` sends content by design. Pattern detection has false negatives |
| Prompt or content leakage in logs | Provider response bodies are not logged; traces do not store prompts or chunks; audit events hold metadata only | Error strings from local components may include file names. Operator restricts log access |
| Runtime token theft | Tokens are high-entropy, stored as SHA-256 hashes, deployment-scoped, rate-limited, revocable; rejections are audited with fingerprints | A stolen token works until revoked. Operator revokes it and reviews `runtime_token.rejected`/`provider.invoke` events |
| Management API abuse | Production profile requires a declared authenticating reverse proxy; CSRF and cross-site checks on `/api/v1` | ForgeAI has no built-in production login. Operator provides the identity boundary |
| Backup leakage | Deletion semantics and backup limits are documented | Deletion does not reach existing backups or provider-side retention. Operator applies backup retention |

## Security configuration matrix

| Setting | Local-only deployment | External-provider deployment |
|---|---|---|
| `privacy.mode` | `local_only` | `external_allowed` |
| Provider endpoints | loopback, private network if allowed, or exact allowlisted origins | any configured endpoint |
| Customer text leaves the instance | no, unless an allowlisted internal endpoint is outside the operator's boundary | yes, to the configured providers |
| `privacy.outbound_policy` | optional defence in depth | choose `deny_sensitive` or `redact_known_patterns` for data with known identifier formats; `allow` is an explicit choice |
| `profile` | `production` for customer data | `production` for customer data |
| `security.storage_at_rest` | `operator_encrypted_volume` | `operator_encrypted_volume` |
| `security.management_boundary` | `reverse_proxy_identity` | `reverse_proxy_identity` |
| Retention | set `retention.traces_days`, `evaluation_runs_days`, `audit_days` to the customer's policy | same |

## Implemented guarantees

1. With `privacy.mode: local_only`, ForgeAI does not transmit to an LLM or embedding endpoint outside loopback, the allowed private network, or the exact allowlisted origins.
2. With `deny_sensitive`, a provider request containing a match for a configured detector or rule is not sent. With `redact_known_patterns`, those matches are replaced before transmission.
3. Deleting a document or knowledge base removes its chunks, embeddings, FTS rows, source-sync records, datasets, evaluation results, and (with opt-in) deployments. `forgeai data compact` removes deleted text from the database files ForgeAI manages.
4. Provider secrets are encrypted at rest. Runtime tokens and demo sessions are stored only as hashes.
5. Audit events and traces contain no secrets, prompts, or document text.

## Operator responsibilities

- Run one ForgeAI instance per customer security boundary.
- Place the database on an encrypted volume and declare it.
- Put `/api/v1` and the UI behind an authenticating reverse proxy and declare it.
- Protect `FORGEAI_MASTER_KEY`, provider keys, the host, and logs.
- Choose `local_only` when content must not leave the environment; otherwise choose the outbound policy deliberately.
- Apply retention to backups and snapshots, and review provider-side data retention.
- Revoke runtime tokens when compromised and review the audit trail.

## Known limitations

- Chunk text, FTS data, and evaluation answers are not application-encrypted.
- Sensitive-data detection is pattern matching for the documented formats only. It does not detect names, addresses, or other personal data.
- There is no tenant isolation and no built-in production login for the management API.
- CLI audit actors are OS user names, not authenticated identities.
- Deletion does not reach backups, snapshots, source systems, or data already sent to external providers.
- ForgeAI cannot verify the operator's declarations about volumes and reverse proxies.

## Claims discipline

Do not state any of the following unless the specific deployment provides the evidence above:

- "personal data never leaves the customer environment" — only for `local_only` deployments whose allowlisted endpoints are inside that environment;
- "no data is sent to external AI providers" — same condition;
- "customer data is encrypted at rest" — only with a declared and operator-verified encrypted volume, and never as an application feature;
- "tenant isolation" — not implemented;
- "all PII is automatically removed" — never;
- compliance with any legal or certification framework — never on the basis of these controls alone.
