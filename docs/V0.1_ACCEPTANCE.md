# ForgeAI v0.1 Acceptance Gates

v0.1 is not accepted by a single green unit-test run. The release requires evidence from all gates below.

## Gate matrix

| Gate | Evidence | Status rule |
|---|---|---|
| G0 — Build / unit | `go vet ./...`, `go test ./...`, static build | all deterministic checks pass |
| G1 — Core E2E | clean DB + mock provider journey through ingest/search/RAG/eval/compare | executable, repeatable, no hidden manual repair |
| G2 — W10 Runtime | Deployment snapshot, Bearer auth, search/chat, restart persistence, revocation | runtime tests + dogfood use |
| G3 — W11 Packaging | GoReleaser four-target artifacts, checksums, native smoke | `scripts/release-smoke.sh` passes |
| G4 — Security & Privacy | #21 with #22–#25 complete | committed security evidence + deterministic tests |
| G5 — TechVit dogfood | #26 complete | real TechVit report under `docs/dogfooding/` |
| G6 — Release | migration/upgrade check + artifact smoke + docs audit | only then create `v0.1.0` |

## Mandatory evidence

### Security evidence

Commit:

```
docs/security/V0.1_SECURITY_EVIDENCE.md
```

It must summarize the implemented guarantees and point to executable tests for:

- local/private mode external-egress denial;
- sensitive-data outbound policy;
- customer-data deletion/retention;
- security audit trail;
- single-tenant production profile;
- runtime token authentication/revocation;
- known limitations and operator responsibilities.

Do not create the file as a ceremonial checkbox before #21–#25 are actually implemented and tested.

### Dogfooding evidence

Commit at least one dated report:

```
docs/dogfooding/YYYY-MM-DD-techvit.md
```

Follow `docs/DOGFOODING.md`. The report must contain real questions, at least one observed failure, the resulting improvement, Before/After evidence, and W10 Runtime API use.

Until #21 is complete, use only TechVit-owned non-confidential/non-personal material.

## Release command

The deterministic gate runner is:

```bash
./scripts/v0.1-acceptance.sh
```

The script is intentionally fail-closed. Missing security or dogfooding evidence fails acceptance.

Real-provider verification is additional evidence and must record provider/model/config explicitly. It does not replace deterministic mock-provider checks.

## Tagging rule

Do not create `v0.1.0` while any of the following remain true:

- W10 or W11 acceptance is incomplete;
- #21 is open;
- #26 is open;
- deterministic acceptance script fails;
- migration/clean-install evidence is incomplete;
- documented product/security claims exceed what is actually implemented.
