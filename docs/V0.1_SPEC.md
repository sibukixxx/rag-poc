## 3. コア interface（domain 層）

```go
type LLM interface {
    Generate(ctx context.Context, req GenerateRequest) (*GenerateResponse, error)
    Stream(ctx context.Context, req GenerateRequest) (<-chan StreamEvent, error)
}

// GenerateResponse は必ず Usage を返す（F-2: コスト計測は day 1）
type Usage struct {
    InputTokens  int
    OutputTokens int
}

type Embedder interface {
    Embed(ctx context.Context, texts []string) ([][]float32, error)
    Dimensions() int
    Model() string
}

type VectorStore interface {
    Upsert(ctx context.Context, vectors []Vector) error
    Search(ctx context.Context, embedding []float32, opts SearchOptions) ([]SearchResult, error)
    Delete(ctx context.Context, filter Filter) error
}

type Loader interface {          // F-5: 外部コンバータ差し込み口
    Supports(mime string) bool
    Load(ctx context.Context, r io.Reader, meta FileMeta) ([]Page, error)
}

type Reranker interface {        // F-7: v0.1 実装は LLM listwise のみ
    Rerank(ctx context.Context, query string, cands []SearchResult, topK int) ([]SearchResult, error)
}
```

Chunk の Hash は `sha256(正規化テキスト + chunker設定 + embeddingモデル名)`。
一致時は embedding を再生成しない。

## 4. モデル設定（LLM Router）— W2 実装済み

```yaml
llm:
  providers:
    default:
      type: openai_compatible
      base_url: https://api.openai.com/v1
      api_key_env: FORGEAI_OPENAI_API_KEY   # ローカル開発の近道（設定されていれば優先）
      api_key_secret: openai                # 未設定なら secrets テーブル参照（`forgeai secret set openai`）
  aliases:                     # 業務ロジックは alias のみ参照
    cheap:   { provider: default, model: gpt-4o-mini }
    normal:  { provider: default, model: gpt-4o-mini }
    judge:   { provider: default, model: gpt-4o-mini }
  pricing:                     # F-8: 単価はローカル設定
    gpt-4o-mini: { input_per_1m: 0.15, output_per_1m: 0.60 }
  currency: { display: USD, usd_rate: 1.0 }   # 例: JPY 表示なら { display: JPY, usd_rate: 150 }
```

デフォルト設定（`config.Default()`）はこの形（`gpt-4o-mini` 3エイリアス）を
そのまま持つ。YAML のマップフィールドは既定値にマージされるため
（`gopkg.in/yaml.v3` の挙動を確認済み）、ユーザー設定ファイルで
`llm.aliases.judge` だけ上書きしても `cheap`/`normal` は既定値のまま残る。

API キー解決の優先順位: `api_key_env` が設定されかつ環境変数が存在すれば
それを使う。無ければ `api_key_secret` で暗号化 secrets ストアを引く。
どちらも解決できなくても `forgeai serve` の起動自体は失敗させない
（`forgeai doctor` が `LLM alias "normal" FAIL` として警告し、実際に
呼び出した際は 401 等の API エラーとして表面化する）。

LLM 呼び出しは Generate（非ストリーミング、評価/Judge 用）と Stream
（SSE、Playground 用）の両方が `usecase.ChatUseCase` を通り、呼び出しごとに
Trace 1件 + Span 1件（kind=llm、tokens/cost/latency）が記録される
（F-2 のとおり Phase 1 で計装済み）。

## 7. 検索仕様 — W4 実装済み

1. クエリ正規化（NFKC）→ ① embedding 検索（cosine, top 30, `internal/adapter/vecmem`）
   ② FTS5 trigram BM25（top 30, `internal/adapter/sqlite/fts_store.go`）
   - **3文字未満のクエリは trigram では0件になる**（トライグラムが1つも作れないため）。
     `LIKE '%query%'` へ自動フォールバック（実機検証で確認、docs/DESIGN_REVIEW.md F-4）
   - MATCH クエリはユーザー入力をFTS5構文としてではなく phrase literal として渡す
     （構文エラー回避のため）
2. **RRF（Reciprocal Rank Fusion, k=60）**でマージ → 上位20件（`rerankPoolSize`）に絞ってから
   任意で rerank、最終的に top_k を返す（`internal/usecase/search.go`）
3. `rerank: true` のとき LLM listwise rerank（alias: cheap, `internal/adapter/llmrerank`）を通す。
   LLM呼び出し失敗やレスポンスのパース失敗時は元の順序へ fail-soft フォールバック（検索自体は失敗させない）
4. レスポンスに chunk_id / document_id / filename / score / page / heading / text を含める
   （引用生成に使用。score は RRF 統合スコアであり、cosine/bm25 の生スコアとは別スケール）
5. 検索実行も Trace に記録（span kind: embed / retrieve / rerank）

## 8. 評価仕様

- Retrieval: expected_documents と検索結果の document 突合で Recall@K / Precision@K / MRR / Hit Rate
- Answer: LLM Judge（alias: judge）で Correctness / Groundedness / Relevance を 0.0–1.0 + reason
- 1 run = dataset × 設定スナップショット。run 間比較で品質 / 平均・P95 レイテンシ / 合計・平均コストを並記
- judge プロンプト自体も prompt_versions で管理（F-11）
